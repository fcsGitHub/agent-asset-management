# M69 调研笔记：日常取用轮（三项）

M68 后的候选只剩快照有效期（读时比对可行）与两件走查中反复出现的小缺口。
三项合为一轮「日常取用」：分享时效、清单导出、个人收藏——都服务「高频取用
资产的日常循环」。

## ① 分享快照有效期 expires_at（GitHub PAT / Zenodo 时效锚点）

GitHub PAT 现在默认强制设置过期时间（安全基线：泄漏面随时间自动收敛）；
Zenodo 记录有 embargo/期限概念。M68 补了主动吊销，但「忘了吊销」才是常态——
有效期让链接自动失效，不需要人记得。

实现口径：创建快照时可选 `expiresAt`（ISO 时间；UI 用天数换算，留空=永久）；
公开端点读时比对 `expires_at <= now()` → **410 SHARE_EXPIRED**（与吊销同为
Gone 语义，但文案区分「过期」与「吊销」——持有者能判断是时间到了还是被撤）；
团队内清单显示有效期与过期态；过期与吊销可叠加（吊销优先报）。不加定时清理
（需要调度基建，已退役项同口径）；过期快照内容团队内仍可查（与吊销一致）。
列授权不变——expires_at 只在 INSERT 写入（表级 INSERT 已授权），不需要
UPDATE 通道。

## ② 目录筛选结果导出 CSV/JSON（CKAN/Dataverse 数据清单口径）

CKAN/Dataverse 都支持把当前检索结果导出为清单（合规盘点、汇报材料、离线
对账）。项目的活动流已有同款导出（RFC 4180 + BOM + 审计盖章），资产目录缺
这一环：治理清单才是「现在团队有什么」的权威面。

实现：GET /assets/export?format=csv|json——过滤参数与 search 完全同一套
（q/type/label/lifecycle/typePrefix/prop/sort），走同一条 queryAssetRows/
scoreAssetRows 管线（导出与目录不可能分叉）；列=名称/类型/版本/生命周期/
关联数/近90天使用/别名数/标签数/是否含制品/完整度分/内容摘要/登记时间。
**属性明细不下发**（与目录同可见面——完整属性走 bundle 下载，导出 JSON 里
如实注记该边界）；上限 500 行，达到上限如实标注截断；导出是敏感可见动作，
盖章 `asset.export` 审计（detail 记格式/条数/过滤范围），动作名进动态过滤。

## ③ 个人收藏 pin（GitHub stars / HF likes 锚点）

高频取用资产（常用模型、常引文档）每次都要搜一遍——GitHub stars 的价值就是
把「我的常用」变成一键可达。实现：user_asset_pins（团队内按用户隔离，
PK(team,user,asset)，资产删除级联）；POST/DELETE /assets/:id/pin；search 附
行级 `pinned`（当前用户视角）+ `pinned=true` 过滤参数；目录行 ★ 切换与
「只看收藏」开关（随 URL 化）；详情页头部同款 ★。

边界如实：pin 是个人便利不是团队治理——不写审计、不进动态（与别名同口径）；
跨用户不可见（行级 pinned 按 auth.userId 计算，过滤同）。

## 范围外（如实记录）

- AI 草稿质量反馈环：仍缺真实使用样本，继续搁置（不伪造）。
- 属性筛选 OR 组合/正则：需括号语法，等值+范围已覆盖治理主流；仍为后续候选。
- pin 的团队级聚合（「最多人收藏」排序）：需要用户行为积累后再说，不预造指标。
